# コード調査・修正とテスト結果（2026-09-13）

## 対象と修正

Arc.WinUI、StandardWinUI、StandardWPF、StandardConsole、ソリューション外のStandardMauiを調査しました。既存のテストプロジェクトとカバレッジ設定はありませんでした。

- 言語一覧：初回参照後の追加登録で古いキャッシュが残る問題、重複登録の失敗で片方の辞書だけが更新される問題、登録と参照の競合を修正しました。公開する辞書は不変のスナップショットです。
- WPFのコマンド：ローカル変数を含むプロパティ式でのキャスト例外、空文字による全プロパティ変更通知の取りこぼし、監視解除後に古いオブジェクトを保持する問題、引数例外の誤ったパラメーター名を修正しました。
- コレクション：重複値や独自の等価判定がある場合の並べ替えを修正しました。比較結果が等しい要素の順序を保持し、位置が変わらない要素のMove通知を省きます。計算量は従来と同じO(n²)です。
- 書式変換：バインディングのカルチャを使用し、無効な倍率入力では例外や不正な値を返さずUnsetValueを返します。nullの書式も処理します。
- 数値処理：WinUIの2倍・3倍のサンプルで計算をlongに拡張し、intの範囲内の入力から誤った符号の結果が生じる問題を修正しました。入力が不正な場合は以前の結果を消します。DPI変換では中間の整数演算のオーバーフローを防止しました。
- URL起動：HTTP/HTTPSの絶対URLを検証してOSの既定ブラウザーで開き、URLをcmdのコマンド文字列へ埋め込む処理を削除しました。WinUIライセンスリンクの二重起動処理も削除しました。
- 起動とウィンドウ：放棄された単一インスタンス用Mutexを回復します。MAUIはコンストラクター内のWindows[0]アクセスをCreateWindowへ変更しました。ウィンドウ位置取得ではネイティブ構造体のlengthを初期化し、取得失敗を確認します。これは[GetWindowPlacementのAPI仕様](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getwindowplacement)に合わせた修正です。
- ダイアログ：WPFの生成・表示をUIスレッドで実行し、非同期表示の失敗が呼び出し側のTaskへ伝わるようにしました。WinUIは同じウィンドウへのダイアログ要求を順に処理します。
- 不要な実行コード：到達不能なnullable bool分岐、未使用のフィールド・メソッド、空のイベント処理、一部の不要なasync処理を削除しました。

コメントアウトされたコードは保持しました。構文解析で元の通常コメントと複数行コメントを比較し、削除・変更が0件であることを確認しています。
